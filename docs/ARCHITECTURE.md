# Endpoint operations architecture

Devices are enrolled by an authenticated operator in a server-derived tenant. IDs and serial aliases are bounded; duplicates are rejected. An observation device receives a 32-byte random bearer credential once, stored as a SHA-256 fingerprint rather than plaintext. Human tokens cannot substitute for that device credential. Rotation immediately replaces its stored hash and increments the asset version. A retired device cannot ingest or remediate.

Device ingestion validates tenant/device scope, a five-minute sentAt window, a unique UUID nonce, source and platform, and the complete strict snapshot. The server stores nonce acceptance and the observation in one transaction. Expired nonce records can be pruned only after their replay window. Observations must be newer than retained evidence; an exact duplicate is recognized without opening duplicate cases. Future reports beyond thirty seconds and reports older than a day are rejected. Compromised agent credentials still permit false reports, so this is authenticated transport, not attestation.

Every check is pass, fail or unknown. Missing numeric facts remain null. A stale observation becomes unknown as a whole. A fresh known failure or unknown check opens a tenant-scoped support case unless a case for that device/check is already open. Closure reads a fresh retained snapshot and requires that exact check to pass. The fingerprint supporting closure is retained. A supervisor cannot simply mark a failing check resolved through the status API.

The synthetic repair only enables a lab firewall field. The plan binds device fingerprint/version, snapshot fingerprint, policy, requester, tenant and expiry. An independent reviewer and independent operator are required. Claim, synthetic mutation, fresh observation, persisted readback, device version, audit events and completed idempotency result share one SQLite transaction. A failed persisted readback rolls all of them back. This limited local guarantee does not extend to a real endpoint or external service.

Asset state transitions are received to assigned/in-transit/retired, assigned to in-transit/returned, in-transit to assigned/returned, and returned to assigned/retired. Retired is terminal. Every transition checks the current version. Assignment requires an owner alias; other states clear it. Shipping integrations and personal address records are deliberately absent. The state records an operator's asset workflow, not proof of delivery.

Support exports whitelist device metadata, observations, diagnostic facts, policy findings and digests. They omit device credentials, recovery keys, process lists, account names and network destination names. The OS collector uses only fixed read-only commands on supported macOS hosts and safe built-in inspection elsewhere. Optional network diagnostics have a bounded operator-selected hostname and fixed TCP/TLS path; the API cannot select destinations or commands. Configured operator diagnostic targets are trusted and receive no service bearer token.

Fleet projection pins the host ID and selected policy IDs. Missing policy responses stay unknown; boolean policy results cannot establish a numeric patch age or administrator count. The endpoint cannot claim to be a native MDM server or guarantee the truth of an imported observation. Storage and audit boundaries are documented in OPERATIONS.md.
